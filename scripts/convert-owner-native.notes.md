## Contract

- `convertHtml` and `convertPage` are pure. Page/component metadata, sibling blocks, nested children, named slots, variants, decoded attribute values, inline CSS and all flow whitespace are retained. IDs use a bounded root prefix and a deterministic tree-path hash. The original wrapper keeps its component ID.
- Reuse `layout.container`, `core.text`, `core.image`, and `core.button`. Structural forms/fields/tables and inert SVG use native semantic tags. Field `type`, `name`, `value`, `checked`, `selected`, `required`, and other attributes use the existing attributes schema; boolean presence is retained. No unimplemented Studio field schema is invented.
- `asset`, `alt`, `href`, `target`, `className`, and `style` use the renderer's existing separate properties. Mixed buttons/links use `props.children`; text-only ones use `label`. Download URLs and supported absolute URLs retain queries/fragments. Relative navigation resolves against the page route.
- `props.collection=true` marks direct sibling lists and card/tile grids, rails, lists or strips with at least two compatible children. Mixed prose, headings, filters, single items, and the fixed daily-track sequence do not qualify. This marks reorder candidates; the converter never reorders them.
- Unsupported content throws `ConversionError` with diagnostics. `inspectHtml` classifies without writing. Scripts, iframes, runtime image slots, active/referenced SVG, comments, declarations, unsupported tags, malformed nesting and unsafe attributes are never silently removed. The strict parser does not repair omitted/mismatched closing tags.
- Inert SVG preserves case-sensitive attributes such as `viewBox`. SVG foreign content, external/reference graphics and animation require a separate runtime/resource policy.
- The default owner-tag snapshot is based on the Studio source read for this lane. Callers can supply `ownerTags` derived from the actual `validateOwnerProps`. The write CLI loads that validator directly, derives its accepted tags and validates output before writing.
- The CLI requires exactly one explicit scope (`--page <absolute path>` or `--all-pages`) and `--pilot-qualified`. The selected page must resolve to one entry in the registered page index. It imports the exact Studio mutations and synchronous history modules through absolute `.ts` URLs; invoke it with Node's `--experimental-strip-types` when separately authorized. All image-byte reads finish before `transact`, and fresh revision checks guard catalog and every selected page write. A single history transaction covers the whole selection.
- Image lookup uses exact reference source paths, never a basename fallback. Replaced catalog sources are not reused for different original bytes. Missing local raster images can later be registered using actual bytes and hashes without modifying those files. Symlinks escaping the project and URLs whose suffix cannot survive the current asset renderer are rejected.
- One unambiguous registered local URL in inline `background` or `background-image` CSS is resolved through the same exact catalog/source resolver as image assets. The component receives both `backgroundAsset` (catalog ID) and `backgroundSourceUrl` (the exact original URL value); canonical inline CSS remains byte-for-byte intact in `style`. Studio renderer integration replaces only `url(backgroundSourceUrl)` with the resolved URL for `backgroundAsset`, preserving gradient layers, composite shorthand, sizing, position, repeat, and other declarations. Conversion does not add `backgroundFit` or a default `cover`. This `backgroundAsset`/`backgroundSourceUrl` pair is the required contract for renderer and owner controls. Multiple/ambiguous URLs remain unchanged with `CSS_ASSET_IDENTITY_PENDING`. Responsive `srcset`/`source` URLs remain exact static attributes until Studio supports typed responsive asset identities.
- Stylesheet-owned image backgrounds are not inline converter inputs and must remain attached to their existing classes/selectors. Current `site.css` examples include `.site-brand::before` (brand crown); `.wo002-play-hero` and its mobile rule (candy kingdom); `.wo002-play-hero::after` (Toadal victory); `.discovery-world .wo002-detail-hero`; `#app .app-conversion-panel` and `#app .app-conversion-panel--production` (gradient plus candy kingdom); `.character-hero-bg` / `.profile-hero-bg` and their mobile rule (desktop/mobile candy kingdom); `.app-product-hero`; and `body:has(.home-hero)` (page background). Keep these URLs, media rules, gradients and class ownership in CSS. Studio's new background art control on native empty div/section/decorative boxes lets an owner replace CSS-only art without moving it into converter-generated inline styles.
- Exactly three bounded `core.rich-text` runtime fragments survive classification. Their generic `runtimeKind` enum is `external-script`, `isolated-frame`, or `dynamic-image`. Each fragment has `runtimeOnly: true`, `readOnly: true`, `locked: true`, `runtimeVersion: 1`, `runtimeKind`, `runtimeSha256` (SHA-256 of the exact stored HTML UTF-8 bytes), `runtimeCodeResources: [{url, sha256}]`, and `runtimePolicy: {id, mode, ...profile}`. The source fragment is capped at 2,048 UTF-8 bytes. Route, original component ID, exact attributes, no inline script body, and the exact runtime slot/profile are all required. No arbitrary scripts, iframes, or dynamic image slots are admitted.
- Frozen policy resources are pinned by SHA-256: Home `home-interactive-discovery.js` `4a516b712dc3e1b276f81b5fe5b2a4cc45bfd978d145a8b13cc8739959686840`, `guest-progression.js` `69984c7ce7b1ff79413b9275e345715a92badc131b4657fd26f4ae98e7c1cee2`, and `manifest-shell.js` `b5997ed5df1d715039835560c7b84a8373fd348b7ca28f9cffa29992ed51802e`; Wicked Bites `public/games/wicked-bites/index.html` `26a8e1f0cc717560f30a786fa9705f4b538f01c742fa120eb1bf7544705f4fec`; Reader `stories-publishing.js` `ab17e0ec3c363a0391740cfa605e5a5be69a027bbd837d624ae0462aa288c504` and `manifest-shell.js` above. The CLI verifies applicable resources before it can enter the write transaction.
- Export behavior is explicit: Studio's current `safeRich` strips all `<script>` tags and their bodies from `core.rich-text`. Home's small `external-script` tag therefore does not emit a second script; the project's advanced code loads `guest-progression.js`, which injects `home-interactive-discovery.js` when `[data-home-discovery]` exists. This preserves the existing runtime behavior and baseline output policy. The reader's advanced code loads `stories-publishing.js`, which populates the exact empty `img[data-reader-page][decoding=async]` slot. The `isolated-frame` retains the original frame element and sandbox profile (`allow-scripts allow-pointer-lock`, fullscreen permission). These three blocks are specialized runtime fragments, never full-page rich HTML.
- Studio integration still needs to consume `runtimeOnly` as an immutable validation boundary and suppress Inspector editing, inline editing, and API mutations. The current rich-text inspector exposes its editor/save controls even when `locked`; converter metadata alone does not enforce read-only behavior. The main-runtime contract is the property set above, with generic `runtimeKind` values and digest/size validation.
