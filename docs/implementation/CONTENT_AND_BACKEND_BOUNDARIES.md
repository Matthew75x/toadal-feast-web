# TOADAL FEAST — Content and Backend Boundaries

## Release A works without backend-heavy systems
Can be public:
- browser games that actually work
- World/Characters/Stories/Media/News
- comics/reader
- guest-local Feast Pass
- local quests/rewards
- App conversion
- local search
- Support/Contact/About/Legal
- Roadmap/Coming Soon/404

## Local guest state
Can include:
- guest ID
- XP/level
- Sparks/Treats
- streak
- badges/discoveries
- quests
- local scores
- reading progress/bookmarks

## Future connected systems
Remain Preview/Planned until real:
- account authentication/sync
- registered player profile
- global/friends leaderboard
- community posting
- Store checkout
- live notifications

## Guest-to-account rule
When accounts eventually launch, existing guest progress must not silently disappear.
Migration/conflict behavior must be implemented and tested before account launch.

## Content platform
Structured entities:
Game, Character, World, Location, StorySeries, Chapter, Media, News, Event, Quest, Reward, Badge, Collectible, Creator, StoreProduct, SupportArticle, RoadmapItem, LegalDocument.
