# Feature Salvage Rules

Codex must inspect donor versions before finalizing page behavior. Do not assume latest means most complete.

## V3 donor value
Strong gamified visual concept and adventure framing: world presentation, rewards, daily/streak/progression, collectibles, dense playful personality.

## V4 donor value
Cleaner maintainable source-driven structure and a useful transitional baseline.

## V5 donor value
Heavier interaction layer and playful/living-site behaviors, including Treat/interaction concepts.

## V6 donor value
Broad living-portal product surface and refined contextual UX. Treat as an important donor despite smaller archive size; archive size is not a proxy for feature depth.

## RC2.1 donor value (if present on ASSIGNATOR)
Historically strongest semantic bottom-right Toadal behavior: route awareness, semantic hover/focus/click state mapping, reward event reaction, minimize/persist behavior, richer Passport/HUD and mobile navigation concepts. Do not restore the old full four-mode console; that specific feature is on ice.

## CP9 / V13 donor value
Strongest modern engineering/product architecture recovered: TOADAL FEAST-first funnel, browser-game library, cartridge/player shell, fullscreen, staging/production boundaries, app handoff, responsive modern structure. Use as engineering baseline, NOT as proof that every feature survived.

## Consolidation rule
For every meaningful feature: KEEP, IMPROVE, MERGE, or RETIRE WITH RATIONALE. No silent regression.
