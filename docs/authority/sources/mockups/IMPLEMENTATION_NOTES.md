# Implementation Notes

## Product truthfulness
Community, Store, account sync, persistent connected leaderboards and similar backend-dependent systems must visually distinguish preview/planned/coming-soon states from available guest-first experiences.

## Feast Pass
Guests begin earning immediately; guest progress is durable local browser data. Exact guest caps/economy remain TBD and must not be hardcoded into product architecture. Accounts later preserve/sync and enable fuller connected identity/reward capability.

## Browser vs App
The website is free browser side-games + discovery. The full TOADAL FEAST flagship game is not represented as fully playable on web. App pages explain Arcade, Puzzle, Feastfall and Infinite as the deeper mobile experience.

## Reactive companion
Treat the bottom-right Toadal companion as a semantic system keyed by route, focused/hovered objects, clicks, rewards, quests, errors and settings—not static decoration.
