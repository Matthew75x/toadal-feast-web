# TOADAL FEAST — Content Publication Rules

## Two independent state systems

### Feature state
`PUBLIC · PREVIEW · PLANNED · COMING_SOON · DISABLED`

Describes whether a product capability works.

### Publication state
`DRAFT · PREVIEW · PUBLISHED · ARCHIVED`

Describes whether a content entity should be publicly discoverable.

Do not merge these concepts.

Example:
- Store feature: COMING_SOON
- a public Store concept explainer page: PUBLISHED

## Source authority
Public content order:
1. current owner-approved copy/data
2. factual current product/release evidence
3. current canonical game/content source
4. approved website copy
5. mockup placeholder content

Lower authority never silently overrides higher authority.

## Mockup rule
Generated titles, dates, scores, biographies, lore, roadmap items and reward values are placeholders unless separately approved.

## Dates
Only publish a date when it is factual and sourced.
Never invent launch/publication dates to fill layout.

## Characters/lore
Generated art/copy cannot create canon.

## Roadmap
Public Roadmap includes only owner-approved public items/status.
Internal work orders are not automatically a public roadmap.

## Legal
Only approved legal text may move to PUBLISHED.

## Build behavior
DRAFT content stays out of public static output by default.
